# 网站图片缩略图与预览

本文记录网站显示图片的当前实现及后续改进建议；不涉及设计验收截图，也不改变原图下载、附件生成输入或业务数据。接口见 [接口契约](api-contract.md)，加载配置见 [部署说明](../deploy/README.md)。

## 已实现

| 场景 | 当前资源与行为 |
| --- | --- |
| 生成结果列表、图库卡片、大图弹窗 | 按实际显示尺寸与DPR选择现有640px/Q82或1600px/Q93等比WebP；下载保留原图 |
| 当前上传附件、当前链路历史附件小图 | 最大256px方形WebP，沿用居中cover裁切，不放大小原件；对话框显示62px，历史记录沿用原显示尺寸 |
| 附件悬停 | 按实际显示尺寸与DPR选择640px或1600px等比WebP，完整展示图片 |
| 站内生成图加入附件 | 复用生成图已有640/1600资源；原图URL继续用于下载与生成输入 |
| 旧任务输入附件 | 兼容已有1600px预览URL；没有新附件的256px方形档位 |

生成图处理见 [thumbnail.go](../internal/studio/thumbnail.go)，附件处理见 [attachment_renditions.go](../internal/studio/attachment_renditions.go)。两者均按访问懒生成并持久缓存；不批量重编码历史图片。附件独立支持PNG/JPEG/WebP/GIF安全解码，保留透明通道并应用EXIF方向，动图生成静态首帧预览。低色数PNG/GIF使用无损WebP，其余小/中档质量82、大档93；附件采用Method4降低首次编码延迟，生成图原有参数不变。原件及提交上游的输入处理保持原有用途。

图片响应先认证并校验归属，包括缓存命中和304；使用私有缓存、Cookie隔离及ETag重新验证。新附件缓存保存MIME、长度、ETag与源图/衍生尺寸，缓存命中的304/HEAD不读取图片BLOB或重复计算哈希。既有生成图与原件的缓存热路径仍沿用原实现。

## 自适应悬停

[附件组件](../frontend/src/features/create/DialogAttachments.tsx) 按原图可视宽高决定布局，按当前卡片中心定位正上方10px；左右保留8px视口空间，上方不足时等比缩小。图片最大316×288 CSS px，外框由图片加固定内距推导：宽度加8px且最小128px，高度加36px，最大324×324px。小图不主动放大；文件名20px高、单行省略。

原图尺寸与衍生尺寸分开使用；旧EXIF宽高可在首次图片加载后纠正。浮窗单独挂到body并按视口定位，避免工作区裁切；输入框增高、滚动、缩放及DPR变化后重新测量。浮窗与卡片之间有透明鼠标通道，并保留短暂离开延迟、键盘聚焦与ESC关闭；异步加载按当前图片和资源身份隔离，避免旧图或过期失败响应覆盖新图。设计来源为指定对话框稿的批准页4007及其四个代表画面，原稿与色板不作为实现素材。

## 资源选择与回退

[共享选图逻辑](../frontend/src/lib/image-renditions.ts) 使用实际显示尺寸、纵横比、裁切方式和DPR计算像素需求，不把640/1600长边标为固定1x/2x，也不重复乘浏览器缩放。高DPR超过小原图清晰度时选择有效像素最多的档位；多个档位相同则优先较小档。固定用途与版本控制缓存数量，不开放任意宽度/质量参数。

隐藏容器或关闭的dialog没有可测量尺寸时暂不选图，不能用1px兜底先选缩略图。弹窗在绘制前打开，图片区域获得真实尺寸后再选择资源，避免冷加载和暖缓存重开时先缩略、后高清的切换闪动。

[图片组件](../frontend/src/components/RenditionImage.tsx) 正常成功路径不增加HEAD请求；仅衍生图失败后检查状态，401/403不转原图，其他失败最多回退一次原图，原图再失败正常显示失败态。原图下载及生成输入不使用裁切小图。

## 后续优化边界

合成照片、文字截图和透明渐变样本用于比较体积、像素及编码耗时，据此为低色数PNG/GIF加入无损分流。该规则不能保证所有文字图无损，也不能宣称82/93对所有图片最优；ICC色彩管理、“衍生图大于原件”的策略与AVIF仍需单独评估，未引入额外编码依赖。新附件的缓存优化不代表旧生成图缓存已一并迁移。

## 审查证据与后续验证

首次审查发现附件仍使用原图，后续改造按上述现行规则补齐。专项浏览器场景见 [image-renditions-check.mjs](../frontend/tests/e2e/image-renditions-check.mjs)，使用真实前端和合成API/图片核对选图与浮窗行为；后端编码与缓存测试见 [attachment_renditions_test.go](../tests/go/attachment_renditions_test.go)，真实MySQL与Go/CSP联调沿用测试矩阵。界面模拟不能代替真实编码或权限验证。

后续实现按 [测试矩阵](../tests/README.md) 验证四种格式、透明/方向/极端比例、小图不放大、历史图首次访问、权限与304、失败回退，以及不同缩放/DPR下的实际请求和画质；使用本地合成样本，不调用收费生图接口。
