# 成熟组件模式补充调研

调研日期：2026-11-06（Asia/Shanghai）。范围：仅通过公开 HTTP 读取官方文档及示例源码，未操作示例网页，未亲测上传、键盘或图片预览交互。以下“文档事实”指来源明确描述或示例源码明确实现的能力，不能视为本项目已有功能。

本项目当前交付为 FigCraft 静态、原生可编辑线框。本调研只借鉴组件关系与状态组织，不引入代码、主题、token、组件皮肤，也不确定最终开发组件库。

## 1. Ant Design X Sender：可分区的对话输入区

来源：

- [官方组件页面](https://x.ant.design/components/sender/)
- [已读取的官方文档源文件](https://github.com/ant-design/x/blob/main/packages/x/components/sender/index.en-US.md)
- [已读取的 footer 示例源码](https://github.com/ant-design/x/blob/main/packages/x/components/sender/demo/footer.tsx)

**文档事实**

- Sender 面向聊天输入场景，提供独立的 `header`、`prefix`、`footer`、`suffix` 内容区域。
- `autoSize` 可以限制输入区最小和最大行数；文档默认最大 8 行，footer 示例使用最小 2 行、最大 6 行。这些是组件或示例配置，不是本项目需求。
- 文档提供禁用、只读、加载状态，以及发送、取消回调。
- `Sender.Header` 支持标题、展开状态及关闭控制。
- footer 示例将辅助功能置于左侧，发送相关操作置于右侧；加载时切换操作按钮。示例采用计时器模拟提交，不能证明真实生成耗时。

**适用于本项目的设计建议**

- 将底部输入区划为“附件行／文本区／参数与发送行”，每个区域使用独立容器，便于 FigCraft 手工调整。
- 模型和参数组成一组，预计积分靠近发送按钮，减少两者关系不明确的情况。
- 输入区向上增长，并设置高度上限，保证 1440 × 900 视口中对话结果仍有足够展示空间。具体高度由首屏布局验证确定。
- 独立标注输入、提交、生成中的状态归属，不把这些状态全部塞进默认画面。

**限制与取舍**

- Sender 本身不定义图像模型、档位、比例、清晰度、数量或积分规则；这些仍需从指定产品调研取证。
- 示例包含语音、搜索、深度思考等功能，本项目没有对应需求，不采用。
- 文档存在可展开附件面板的能力，不代表本项目必须折叠附件。首张线框建议直接显示已选图片，使参考图是否生效更明确。

## 2. Ant Design X Attachments：附件列表与输入区组合

来源：

- [官方组件页面](https://x.ant.design/components/attachments/)
- [已读取的官方文档源文件](https://github.com/ant-design/x/blob/main/packages/x/components/attachments/index.en-US.md)
- [已读取的 Sender 组合示例源码](https://github.com/ant-design/x/blob/main/packages/x/components/attachments/demo/with-sender.tsx)
- [已读取的基础示例源码](https://github.com/ant-design/x/blob/main/packages/x/components/attachments/demo/basic.tsx)

**文档事实**

- Attachments 用于展示附件集合，继承 Ant Design Upload 的属性；可配置附件列表、最大数量和禁用状态。
- 列表溢出方式提供换行、横向滚动和纵向滚动；图片配置可对接 Image 组件。
- 文档区分常规空状态与拖入状态的提示内容，可以指定拖放区域。
- 组合示例将附件列表放入 `Sender.Header`；入口控制面板展开，存在附件且面板收起时显示提醒点。
- 组合示例以浏览器对象 URL 生成文件预览，并明确使用 `beforeUpload={() => false}` 阻止真实上传；提交也标记为 Mock Submit。该示例证明组合方法，不证明网络上传成功、格式校验或模型支持的图片数量。

**适用于本项目的设计建议**

- 已上传参考图作为输入区子组件，使用缩略图、简短文件名或编号、单项移除入口表达；显式显示当前数量，便于多图场景核对。
- 为 1440 × 900 固定视口优先考虑单行附件列表，溢出横向滚动或显示剩余数量，避免多行附件挤压对话结果。具体方式待结合参考网站真实表现选择。
- 将“选择文件”“本地预览已出现”“可用于本次生成”视为可能不同的状态；真实产品若存在上传过程，需独立表达处理中和失败。
- 附件数量上限、大小和格式只采用经指定网站对应模型验证的值；未知则保留待确认标注。

**限制与取舍**

- 拖放和粘贴图片是可借鉴能力，不自动纳入需求。
- 组件示例支持多种文件，本站范围为图像，不据此扩张音频、视频、文档上传功能。
- 本次未亲测附件预览、移除、溢出或拖放行为；参考产品中的实际上传状态仍由浏览器操作验证。

## 3. Ant Design Image / PreviewGroup：图库中的查看模式

来源：

- [官方组件页面](https://ant.design/components/image/)
- [已读取的官方文档源文件](https://github.com/ant-design/ant-design/blob/master/components/image/index.en-US.md)
- [已读取的分组预览示例源码](https://github.com/ant-design/ant-design/blob/master/components/image/demo/preview-group.tsx)

**文档事实**

- Image 支持图片展示、加载占位和加载失败替代图，可独立配置预览状态及预览图源。
- PreviewGroup 支持图片集合、当前索引、图片切换回调和计数显示定制。
- 预览文档提供关闭、缩放、移动及工具栏定制等能力；示例将两张图片归入同一预览组。
- 文档允许缩略图与预览使用不同图源，因此不要求列表加载完整原图。

**适用于本项目的设计建议**

- “我的图片”先明确缩略图浏览与大图查看两层结构。点击图片进入大图查看，是值得纳入首轮图库设计的建议。
- 同一次生成的多张结果可形成查看分组，显示“当前张／总张数”；图库中的切换范围须明确为当前筛选集合或当前生成组，不能让编辑者猜测。
- 详情状态优先保留关闭、前后切换和图片计数；是否增加缩放、下载或生成参数面板，待产品调研后推荐。
- 用独立可编辑的预览容器、图片占位区与工具栏表达静态状态，不使用整页截图作为设计节点。

**限制与取舍**

- Image/PreviewGroup 不负责图库分类、搜索、排序、收藏、删除或批量管理，不能把这些功能归因于此组件。
- 文档里的旋转、翻转等能力不等于用户需要图片编辑器；本轮不由组件能力反推额外需求。
- 预览样式、遮罩和工具栏仍需按中性线框设计。本次没有亲测焦点、键盘、缩放或组内切换体验。

## 建议采用范围

| 设计区域 | 推荐借鉴 | 暂不据此决定 |
| --- | --- | --- |
| 底部输入区 | 附件、文本、参数、提交的明确分区；输入高度上限 | 具体模型参数、积分、语音和搜索 |
| 上传后状态 | 附件子组件、数量、单项移除和溢出策略 | 数量上限、格式大小、拖放与粘贴是否纳入 |
| 我的图片／结果查看 | 缩略图到大图、同组切换、计数、关闭 | 收藏、删除、批量操作及完整编辑工具 |

以上均为供审阅的设计建议；最终取舍以用户已确认范围和指定参考网站的实际调研为准。官方仓库链接指向可变化分支，本文记录的是调研日期读取到的内容。
