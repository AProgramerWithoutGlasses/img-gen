# 我的图片：入库、排序与文件夹调研

访问日期：2026-11-06（Asia/Shanghai）。本轮实测页面均核验为 **1440 × 900** 桌面视口；Base Design 复用同日已完成的桌面实测，不以窄屏作为布局参考。交付仍为 FigCraft 原生可编辑的静态线框，不开发交互或接入真实图库。

此前调研验证了创作输入和 Base 的图片布局，**没有验证 AI 图库的新图入库、精确排序或文件夹管理**。本报告补充这些证据，并区分用户决定、亲自操作的事实、官方文档与待审建议。

## 本轮范围与已确认规则

- 用户要求加入自定义文件夹和对应管理，允许**新建、重命名、删除文件夹**。
- 用户已选择**一张图片可属于多个文件夹，归类不复制图片**。
- 本轮不设计**图片删除或回收站**。文件夹删除与图片删除必须分开表达。
- 创作结果中的“添加”仍表示加入当前待发送附件栏，与图库分类无关；图库整理使用“加入文件夹”“管理文件夹”等明确措辞。

前期笔记中“文件夹删除也暂不设计”的范围记录已被后续确认更新；以本节为准。

## ArtCraft：全部资源、未归类和文件夹的关系

**实测事实**

- 左侧 Assets 区有 Library、Unfoldered、Folders 和新建入口；Folders 下显示自定义文件夹。主区顶部也提供 All Assets／Folders／Unfoldered／Tags 切换。
- 新建测试文件夹后，侧栏和主区出现同名入口；重命名后，两处名称同步更新。
- 单张测试图通过 Add to Folder 加入文件夹，进入后可见这张图；文件夹标题旁有重命名及 New subfolder 入口。子文件夹仅观察入口，没有创建验证。
- 对这张图执行 Remove 后，文件夹显示 `This folder is empty.`；返回 Unfoldered 时仍能看到原来的两张测试图。此次操作移除了分类关系，没有删掉测试图。
- 列表显示日期分组及 Refresh library 入口。日期标题或刷新按钮的存在不能证明精确排序规则或自动刷新行为。
- 删除空测试文件夹时，确认框原文为 `Subfolders move to the top level. Items stay in your library.`。执行删除后，Folders 为空，All Assets 仍显示两张几何测试图。**执行结果只验证空文件夹删除**；“项目保留在图库”是界面明确说明，未通过删除含图片文件夹验证，子文件夹移到顶层也未实测。

**借鉴与限制**：采用“全部图片／未归类／自定义文件夹”的清晰关系；空文件夹应提示加入已有图片。本项目只有图像，不复制多媒体类型、Tags、复杂工具导航或子文件夹。

证据：[新建](../../outputs/research/gallery/artcraft-folder-created.jpg)、[重命名后有一图](../../outputs/research/gallery/artcraft-folder-one-asset.jpg)、[移出后空文件夹](../../outputs/research/gallery/artcraft-folder-removed-empty.jpg)、[未归类仍保留两图](../../outputs/research/gallery/artcraft-unfoldered-restored.jpg)、[删除空文件夹确认](../../outputs/research/gallery/artcraft-delete-folder-confirm.jpg)、[清理后图片保留](../../outputs/research/gallery/artcraft-cleaned.jpg)。同名 `.txt` 保存页面结构及视口尺寸。

## Krea：多选整理与一图多文件夹

**实测事实**

- 页面左侧为产品导航，中央按日期显示图片，右侧为资产搜索、All、类型与 Folders 列表。新建文件夹入口位于 Folders 标题旁。
- 资产原有 5 张，其中 2 张为本轮可辨识的几何测试图，另 3 张为原有风景图。
- 选中两张测试图后，底部出现选择工具栏，含已选数量、Download、Add to folder 等。打开文件夹菜单后可新建或勾选目标文件夹。
- 将两张图加入文件夹后，文件夹数量为 2；重命名更新名称。再次打开归类菜单，可见 `2/2` 和已勾选状态。
- 取消该归属后，文件夹变为 0 并显示空态，All 仍为 5；这验证了移出文件夹与删除图片的区别。
- 将同两张测试图同时加入两个文件夹后，两个文件夹都显示 2，菜单两项均为 `2/2` 且勾选，All 仍为 5。此操作验证了界面上的**多文件夹归属且不增加全库图片数**，不对内部存储实现作推断。
- 页面结构中该按钮的辅助名称为 `Move to folder`，可见文字却是 `Add to folder`。本项目应依据实际行为使用“加入／管理文件夹”，不沿用会暗示单归属移动的名称。
- 用户确认后，先将测试图从两个文件夹移出，再删除两个空测试文件夹。确认框提示 `This cannot be undone.`；删除后 Folders 为空，All 仍为 5。只验证空文件夹删除，没有据此推断删除非空文件夹是否影响图片。

**借鉴与限制**：最适合本项目的是多选后集中整理、多个文件夹归属、文件夹与全库数量保持一致。本项目批量“加入文件夹”仅新增关联；移出另设入口，不直接照搬 Krea 取消勾选即移出的操作。无需照搬额外的右侧资产栏、多媒体分类、收藏、共享或图片删除。两张测试图只能证明已测操作，不代表容量上限。

## ImageAT 与 Base：可用信息和边界

ImageAT 已登录 Dashboard 显示可用积分和总生成均为 0，图库 Images (0)，提供 Create Your First Image 引导。空库下无法验证生成图的加入位置和管理菜单，本轮没有为填补证据而付费生成。未看到文件夹不代表整个产品没有文件夹功能。证据：[Dashboard 空态](../../outputs/research/gallery/imageat-dashboard-empty.jpg)。

Base 的价值仍是图片优先的**行对齐、宽度变化**网格，支持不同图片比例，属于已有同日实测。该布局不是等宽列瀑布流；查看行为是进入项目详情。具体记录和证据见 [原调研](website-research.md) 的 Base Design 部分。本项目不复制其行业分类，也不把 Base 当作文件夹管理依据。

## 补充官方模式：Adobe 与 Leonardo

### Adobe Firefly（官方文档，非实测）

- [生成历史文档](https://helpx.adobe.com/cn/firefly/web/access-your-files/view-generation-history.html)明确说明：生成媒体自动保存在“文件 → 生成历史记录”；下载保存到本地设备。
- [整理文档](https://helpx.adobe.com/cn/firefly/web/access-your-files/organize-your-generations.html)说明：可选一个或多个生成内容，由底部“添加到…”工具栏打开目标位置选择器；整理到“项目”或“您的文件”时**创建副本**，生成历史原件保留。
- 可借鉴自动收集与后续整理分离、批量工具栏和位置选择器。**不采用副本规则**：用户已明确本项目归类不复制。团队项目、跨应用文件、共享等也不在本轮范围。

### Leonardo Collections（官方文档，非实测）

[官方文档](https://intercom.help/leonardo-ai/en/articles/9047341-collections)描述了单图三点菜单 Organize、整次生成整理、Library 中 Select 后批量 Organize，并可在选择目标时新建 Collection。还支持生成前指定 Collection、嵌套集合、重命名和 ZIP 下载。

可借鉴“单图与多选使用同一个归类入口”、在目标选择器中创建文件夹。生成前预设归属、嵌套和 ZIP 下载会扩大当前设计，暂不采用。套餐中 Collection 的数量限制只属于该产品，不引入本项目。

删除部分文档明确：默认只删除 Collection；启用 Delete Source Images 才同时删除内容。这与 ArtCraft 确认框中的“图片保留在图库”共同支持区分分类容器与图片；前者是官方文档，后者是界面说明，**非空文件夹删除后保留图片仍未操作验证**。本项目不提供 Delete Source Images 或图片删除选项。ArtCraft／Krea 已完成空测试文件夹的删除，事实与范围见前文。证据：[Leonardo 官方正文快照](../../outputs/research/gallery/leonardo-collections-official.txt)。

## 本项目建议：新图如何放入（待审）

以下是依据上述模式提出的本项目规则，**不是任何参考站已验证的精确排序**：

1. **一次生成结束后，将其中成功图片一起放入图库。** 最新入库的一组排在最前，同组按输出编号相邻排列；只有成功图片进入“全部图片”和“未归类”。生成中或失败继续在创作对话中表达。这样同一批不会在浏览中陆续插入、打乱位置；代价是图库可能比创作页稍晚出现结果。
2. **浏览途中保持当前图片位置。** 有新结果时显示“有新图片 · 更新”，点击后显示最新内容；重新进入图库直接显示最新。正在查看某个文件夹时，未归类新图不会自动加入该文件夹。
3. **归类不改变图片的原始顺序。** 文件夹展示该集合中的图片，沿用全库的入库顺序；加入或移出分类不把旧图片变成“新生成”。

图片按原比例从左上依次排入行对齐网格。更新后可以重新分行，但原有图片之间的先后顺序保持。日期分组可以辅助浏览，不需要新增批次卡片、重复状态文字或多套排序控件。

如果后续要求成功一张立即入库，应再调整同批排序策略；本轮先用上述整次生成归组方案供审阅，不增加等待时限或后台队列规则。

## 文件夹关系与最小管理建议

**用户已确认多归属、不复制**；据此建议以下界面规则：

| 操作／集合 | 建议规则 |
| --- | --- |
| 全部图片 | 同一图片只出现一次，不受文件夹数量影响 |
| 未归类 | 仅显示不属于任何文件夹的图片 |
| 加入文件夹 | 选择一个或多个目标，确认后只新增关联；已有归属不撤销，也不重复新增同一关系。图片在全部图片中的位置不变 |
| 从当前文件夹移出 | 在当前文件夹单独提供移出操作，只移除当前关系；其他文件夹不变。没有剩余归属时回到未归类 |
| 新建、重命名 | 只处理文件夹名称；建议单层目录，名称不能为空，重名时就地提示 |
| 删除文件夹 | 只删除该文件夹及其归属关系；图片和其他文件夹归属保留。确认框明确“图片不会被删除”，不提供同时删图选项 |
| 多选加入 | 显示选中数量及目标文件夹中“全部已加入／部分已加入／尚未加入”的状态；部分已加入可补齐缺少的关联，全部已加入无需重复操作。取消目标选择只取消本次待添加，不移除既有归属 |
| 文件夹为空 | 提供“从全部图片添加”入口；与“全库还没有生成图片”的空态区分 |

删除文件夹的权限已确认；“只删除容器、保留图片”的具体规则是本项目建议，线框应明确表达。批量加入只新增关联，移出单独执行，两者不混用。多选的部分归属状态是为本项目补全的静态设计建议，本次 Krea 实测覆盖的是 `2/2` 全部已归属；没有据此宣称本项目交互已开发。

建议保持现有 280 px 可展开侧栏，在“我的图片”下组织全部图片、未归类和自定义文件夹；中央仍以图片网格为主。管理入口放在文件夹名称旁的更多菜单，多选时显示集中工具栏。大图查看保留当前集合的前后切换，新增归属信息／管理入口即可，无需扩成图片编辑器。

最小静态覆盖：全部图片与新图提示、文件夹内浏览、选择整理及多归属、创建／重命名、删除文件夹确认、文件夹空态；现有大图查看随之更新。以上可用少量独立状态和局部标注表达，避免为每个组合单独建立完整页面。

## 本轮不采用

- 图片删除、回收站、同时删除源图。
- Adobe 的归类复制、团队共享项目。
- 多层文件夹、生成前指定文件夹、拖放排序、ZIP 批量下载。
- 因参考站具有而直接加入的收藏、搜索、媒体类型筛选或复杂排序。
- 未经实测的自动生成归档时刻、网站精确批内顺序、付款／失败后的存储处理。

本报告支持静态设计决策，不证明这些规则已在产品中实现。后续设计应将已确认的文件夹多归属与待审的入库排序、刷新、文件夹删除语义分别标注。
