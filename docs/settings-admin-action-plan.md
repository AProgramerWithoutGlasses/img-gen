# 设置与管理员面板行动报告（待确认）

日期：2026-11-06。状态：调研与计划已完成，尚未开始本轮 FigCraft 设计。

## 1. 推荐方案

从现有侧栏底部“我的账户 → 设置”进入独立的全宽设置页面。设置页沿用现稿的灰白线框、字体、控件与 1440 × 900 尺度，保留 280 px 侧栏的空间关系。

进入设置后，左侧替换为设置目录，顶部提供“返回创作”；离开设置时保留原对话上下文是设计目标。目录将个人设置和管理员面板分组，右侧展示当前栏目内容。管理员表格获得完整主内容宽度，不挤进窄小设置弹窗。

推荐导航：

```text
← 返回创作

个人设置
  账户与安全
  外观与输入
  积分

管理员面板（仅管理员）
  用户管理
  请求记录
  模型价格
```

此方案更新上一版“在创作主侧栏直接增加管理员面板”的建议：管理员面板纳入设置，统一使用一层栏目导航，不再叠加一套三级导航。普通用户不显示管理员组；访问受限的状态仍需表达，不能把隐藏入口当作实际权限校验。

## 2. 设置页面放什么

| 栏目 | 首轮建议内容 | 操作与边界 | 依据 |
| --- | --- | --- | --- |
| 账户与安全 | 用户名、角色、账号状态、创建时间；修改密码入口；退出登录 | 信息先只读；密码修改建议为当前密码／新密码／确认新密码。密码和登录会话规则待产品确认，不推定管理员更新账号与个人改密必然完全相同 | 管理员截图已有账户字段；ArtCraft Account 与 Krea Account／Profile 补查 |
| 外观与输入 | 浅色／深色／跟随系统；“Enter 发送”开关与快捷键说明 | 建议开关默认关闭：Enter 换行，点击发送；开启：Enter 发送、Shift+Enter 换行。现有账户菜单的主题快捷入口与这里是同一偏好，不成为两个独立设置。中文输入法候选确认不得触发发送 | 当前项目已有浅／深主题；Krea Appearance；ArtCraft General |
| 积分 | 当前余额、充值入口、简短用途说明 | 复用已有积分信息和充值入口，充值目的地待定义；首轮不扩展支付弹层、订阅套餐、发票或积分流水。面向用户的价格说明按已确认规则组织，不展示管理员编辑控件 | 现稿已有余额与充值；用户提供的每张图积分规则 |
| 管理员面板 | 用户管理、请求记录、模型价格 | 全局管理数据与当前用户的个人设置明确分组；创建用户、积分调整、价格修改分别显示影响对象 | 用户提供的管理员截图；Krea 的 Account／Workspace 分组仅作组织参考 |

上述是供本次确认的推荐范围；不继承旧 img-gen 的主题、token、页面或实现。浅／深／系统三个选项不意味着本轮同时绘制所有页面的双主题皮肤。

## 3. 创建用户：本次新增信息

四个字段来自新截图，视觉重新按现项目设计：

| 字段 | 截图信息 | 计划中的表达 |
| --- | --- | --- |
| 用户名 | 3–32 位；字母、数字、下划线、点、连字符；以字母、数字或下划线开头 | 输入框下持续显示简短规则；必填、格式错误、重名作为独立校验状态。字母字符集的精确定义留待实现前确认 |
| 角色 | 默认显示“普通用户” | 默认普通用户；管理员列表已证明有管理员角色，建议提供普通用户／管理员两项；下拉完整取值及哪些管理员可授予角色仍待明确 |
| 账号状态 | 默认显示“启用” | 默认启用；停用为建议补充状态，实际完整取值待确认 |
| 初始密码 | 4–128 字节 | 保留“字节”口径，不误改为“字符”；密码默认遮蔽，建议提供显示／隐藏。字节编码口径待开发前确认，不填入真实密码 |

表单建议使用用户列表右侧抽屉：顶部“创建用户”与关闭入口，正文四个字段，底部“取消／创建用户”。按钮从截图的“保存用户”改为更明确的“创建用户”是文案建议。

成功后关闭抽屉并更新列表；失败时保留非敏感输入并显示具体错误；密码是否保留按错误类型和产品策略另定。不要记录密码到提示消息或设计数据。

截图同时出现“更新账号后，该用户的所有登录会话将失效；已提交的任务继续处理”。这条信息明确描述更新已有账号：

- 新建用户表单只展示初始密码规则，不原样附带“更新账号”警告。
- 在编辑已有用户的相关确认区域展示会话影响与任务继续处理的说明。
- 究竟哪些字段的更新会触发全部会话失效，仍需在细化编辑表单时确定，不能从一段文案推定触发范围。

## 4. 管理员三个栏目

### 用户管理

- 顶部用户名搜索与创建用户；表格列为用户名、角色、状态、可用积分、创建时间、操作。
- 保留当前账号标识，以及管理、积分、请求记录入口。
- 创建用户按第 3 节设计；“管理”展开字段和积分调整规则仍未完整提供。
- 积分调整建议显示对象、当前余额、变动值、调整后余额；是否支持扣减、原因是否必填、是否允许负余额均不预设为既定规则。
- 从用户行进入请求记录时带入用户筛选；清除条件与返回列表路径可辨认。

### 请求记录

- 筛选保留用户、提示词、状态、记录范围、今天／3 天／7 天、自定义起止时间、筛选／清空。
- 时间说明体现浏览器时区；快捷范围包含今天，结束时间更新的具体时机在交互细化时定义。记录范围除“全部记录”以外的选项仍未知。
- 保留匹配请求数，以及已完成／处理中／失败数量；统计与当前筛选结果一致。
- 表格保留用户名、请求时间、输入／模型、生成秒数、消耗积分、状态、生成图片／报错。
- 长提示词用摘要，结果用缩略图；点击查看完整请求详情。请求详情抽屉是设计建议。
- 失败原因与空结果分别表达；不编造退款、自动重试、耗时或排队数量。

### 模型价格

- 保留五个模型，名称与现有创作页统一：Gemini 3 Pro Image、Gemini 3.1 Flash Image、GPT Image 1.5、GPT Image 2、GPT Image 2.5 Sunburst；机器标识作为次级文字。
- 表格保留单张积分、最近修改时间、逐行保存，以及刷新价格入口。
- 保留截图中的业务说明：非负整数、0 免费、同模型生成与编辑同价；修改只影响之后提交的任务，已提交任务保留原价；以已保存价格为准。
- 待保存、保存中、已保存、保存失败清楚区分；有未保存编辑时刷新／离开需要处理提示，避免静默覆盖。

## 6. 验收重点

1. 当前灰白线框与字体、侧栏关系一致，截图只供业务信息，不沿用黄色或切角风格。
2. 账户设置针对当前用户；管理员操作明确针对被管理用户或全局价格，避免对象混淆。
3. 普通用户的页面没有管理员导航；无权限状态单独表达。静态稿不宣称已实现鉴权。
4. 创建用户包含四个字段和准确的长度单位；新建与编辑的影响说明不混用。
5. 设置页主题和账户菜单主题保持同一状态；发送快捷键说明无歧义。
6. 请求记录包含全部已提供字段；价格说明保留新旧任务的生效边界。
7. 有修改行为的页面明确保存反馈和离开时处理；各类状态标明属于已提供规则还是设计建议。
8. 本轮仅本地静态设计，不接后端、不同步业务数据、不 push、不部署。
