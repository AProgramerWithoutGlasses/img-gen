# 首张线框交付与编辑说明

日期：2026-11-06。阶段：四站调研完成，首张图像创作页待审阅。按已确认的执行顺序，主画面审阅后才扩展“我的图片”和其他静态状态。

## 文件与画面

- 原生设计文件：[design/start.figcraft](../design/start.figcraft)。使用安装版 FigCraft 打开，亦可运行 `npm run design:open`。
- 页面：`01 · 图像创作`，一张顶层画框 `图像创作 · 结果与参考图 · 1440×900`，节点 611。
- 画面尺寸：1440 × 900。侧栏 224 px，页头 72 px，输入区宽 1040 px、高 202 px，距视口底部 24 px。
- [实时画布截图](../outputs/design-preview/canvas.png)；[便于审阅的同版 PNG](../outputs/wireframe-v1.png)。截图位于 `outputs/`，不提交 Git。
- 无网页代码、原型连线、动画或后端连接。画面中图片为原生线框占位，不是实际生成结果。
- 积分余额 1,280 与预计 12 积分都是演示数值；没有确定本项目定价，也没有付费生成。此说明同时保存在画布评论 1。

## 页面与组件组织

画框内分为 `01 侧栏`、`02 页头`、`03 对话工作区 / 第1轮`、`04 底部输入区 / 下一轮待发送` 四个区域。结果组与附件列表使用横向自动布局，其余区域按固定桌面画面定位。

| 主组件 | 节点 | 复用和可编辑内容 |
| --- | --- | --- |
| 侧栏 / 导航项 | 618 | 名称文本、选中指示；“我的图片”为未选中实例 |
| 结果 / 图片卡片 | 653 | 图片标题、结果编号；第二张结果为实例 |
| 输入区 / 附件项 | 677 | 文件名、格式与状态；第二张附件为实例 |
| 输入区 / 模型选择 | 697 | 模型标签、当前名称、下拉图标 |
| 输入区 / 参数选择 | 701 | 参数名、当前值；比例、清晰度、数量为实例 |

共 111 个内容节点，5 个主组件、6 个实例。文本、边框、图标、图片占位线均为原生可编辑对象；整页未栅格化。组件主件直接位于代表画面内，不额外建立大型规范板。编辑主件会同步实例；只改一项时使用实例文本属性覆盖。

6 条本地画布评论分别标注：演示数据、消息与结果归属、待发送附件归属、模型条件、用户菜单范围、图库后续范围。组件条件也保存在节点 `pluginData.designNotes` 中。

## 主要关系与状态

| 状态或区域 | 本轮表达 | 后续安排与证据边界 |
| --- | --- | --- |
| 一轮用户消息对应两张结果 | 已绘制，消息和结果同属第1轮容器 | 多轮重复同一层级；图片查看在后续状态中表达 |
| 下一轮上传两张图片 | 已绘制，附件属于底部待发送消息 | 单项移除已在 ImageAT 实测；文件名/状态文案是本项目组织方式 |
| 模型支持档位 | 已绘制 Sunburst 的“高”档位 | 完整选项按参数表；菜单展开稿后续制作 |
| 模型不支持档位 | 画布评论明确两个 Gemini 模型隐藏档位 | 审阅后制作无档位局部状态 |
| GPT Image 1.5 | 参数表与评论明确无独立清晰度时隐藏 | 审阅后制作参数收缩状态 |
| 初始空状态、无附件或单附件 | 未扩展整页 | 首稿通过后制作所需局部或整页状态 |
| 上传中、上传失败 | 上传中禁用发送有 Krea 实测依据 | 失败样式为后续设计建议，非已验证站点行为 |
| 生成中、失败、积分不足 | 尚未制作 | 未付费生成；若需要产品行为证据，再找可免费生成案例 |
| 用户入口 | 已绘制，评论写明展开后的账号、积分充值、主题、设置关系 | 展开菜单在下一轮；独立设置页与充值流程范围外 |
| 我的图片 | 侧栏入口已绘制 | 下一轮制作浏览和查看；下载、回到来源对话仅为建议 |

模型取值统一参考 ArtCraft，以避免混拼不同站点配置；[参数表](research/model-parameters.md) 保留 ImageAT、Krea 的差异。未验证的上传数量上限、格式大小限制、后台组合约束和积分算法均未写成既定规则。

## 调研与验证

- [网站调研](research/website-research.md)：四站正式布局观察与交互检查均核验实际视口为 1440 × 900；早期窄屏入口检查不用于设计。
- [参数表](research/model-parameters.md) 与 [Gemini 别名](research/model-aliases.md)：五模型配置来源、官方别名及证据边界。
- [成熟组件模式](research/component-patterns.md)：Sender、Attachments、Image.PreviewGroup，仅采用结构和状态组织，没有确定代码组件库。
- `npm run design:verify` 通过：1 页、1 张 1440 × 900 顶层画面、111 内容节点、无缺失字体与审计警告。
- 独立视觉检查和最终实时截图检查未发现截断、重叠或越界。实时画布 PNG 与本轮磁盘导出 PNG 的 SHA-256 完全相同，确认显示内容一致。该检查不等于交互测试；本阶段没有可操作页面。
- `npm run design:snapshot -- 611` 的路径查找未识别已打开文档。复核桌面 `doc.list` 与 `inspect_document` 后，使用同一附加 MCP 的文档 ID 5 调用 `screenshot`，将真实实时画布保存到上面的截图路径。没有拿旧磁盘导出替代实时画布，也没有修改连接脚本。

本轮只改设计与文档，未修改网页或自动化源代码，因此未运行网页构建与连接 smoke。审计、导出、实时截图均使用当前安装版 FigCraft。
