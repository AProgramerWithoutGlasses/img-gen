# Marathon 风格的工作室界面

这是经局部双主题试点检验的 v0.1 设计指引，不是 Bungie 官方规范。保留功能明确的几何结构、展示／操作／数据的字体分工、集中的高饱和强调，以及有明确终态的短动效。

## 先判断范围

研究、局部试点与完整产品改造分别处理。UI Studio 当前用户要求：试点可以自主推进，全面设计须明确批准。读取当前对话的授权；不要把本 skill、已有样张或选中某个方向当成新的批准。当前项目要求先修改并保存指定 FigCraft 工作稿，再同步前端；试点放在明确的试点页面中，保留用户现有工作。

UI Studio 的指定稿为仓库中的 `design/ui-studio-design.figcraft`，前端为 `frontend/`。使用前核对项目现行说明、目标文档、选区与未保存状态。研究包的设计建议不能覆盖服务端能力和业务规则。

## 按任务读取

- 字体、颜色、排版、形状与主题：读 [基础规范](references/foundations.md) 和 [变量](references/tokens.json)。
- 具体控件、状态和业务映射：读 [组件规则](references/components.md)。
- 过渡、加载、结果呈现与减少动态效果：读 [动效规则](references/motion.md)。
- 需要判断某种效果是否来自原作、属于何种媒介：读 [证据与采用边界](references/evidence.md)。
- 观察当前试点强度：查看 `assets/` 的浅深主题样张。这些图片是本项目自己的试点，不能冒充游戏画面或定稿。

## 做出设计决定

先确定用户当前任务、主要动作、必要文字、状态和内容密度，再分配风格。C / STUDIO 是当前研究建议的工作界面起点，A / FIELD 与 B / SIGNAL 保留为较温和和较强烈的选择；用户的最新方向优先。

每个方案同时提供浅色与深色，保持语义与结构一致，分别检查文字、边界、焦点、遮罩和图片舞台。用真实中文长标签、模型名称、数字、错误和空状态检验字阶。必要信息不依赖微小大写字、连续动画或纯颜色。

色彩区分基础面、品牌强调与业务语义。主动作获得明确强调，照片和数据获得稳定背景。图标优先可辨认轮廓；切角、条纹和编码标记围绕功能锚点使用。素材的陌生感、工业感与故障感各有具体场景，不能将片中受损屏幕的低可读性带到日常输入。

商业原作字体未随本包提供。试点采用系统字体；更换字体先核对许可、中文覆盖、数字与跨平台回退。不要从游戏网站提取字体文件作为默认产品依赖。

## 交互和反馈

为默认、悬浮、按下、键盘焦点、禁用、处理中、错误与成功分配可辨认状态。动效先说明触发、变化对象、稳定终态和打断方式，再选择时长；120／180／240／320ms 是本项目建议，不能说成游戏实测值。减少动态时保留状态和结果，去掉不必要位移与循环。

UI Studio 的生成控件遵循当前已验证参数；附件顺序、失败不自动重试、部分成功保留图片、费用与权限由服务端决定。数值滑动条研究不构成新增模型参数的授权。

## 输出与核对

交付包含：核心取舍、双主题画面、关键状态、动效说明、字体／素材依据、设计与代码同步状态。用实际浏览器操作检查焦点、弹窗、长内容、窄窗口和减少动态效果。明确区分静态图、可操作试点与真实业务验证。

本包已做结构检查，并用于整理现有试点规则；尚未完成独立代理对未知组件的行为验证。完整设置／管理页和正式字体仍需在获批的全面设计阶段检验。
