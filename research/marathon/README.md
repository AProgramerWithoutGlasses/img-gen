## 1. 目标与项目基础

把项目现有中性界面视为等待美术适配的结构底座，研究一套具有鲜明身份、适合中文生图工作室、可以持续扩展的视觉与交互语言。成果应能直接指导按钮、侧栏、对话框、输入区、菜单、滑动条、图片展示、数据表格和对应动效的设计。

用户补充的明确要求：**浅色和深色主题均为完整交付项**，从探索样张到最终页面、组件状态、设计变量和动效演示都覆盖两套主题。全部研究资料与成果集中在项目根目录的 `marathon-design-research/` 文件夹内，本文件作为统一入口。

阶段授权：研究、自动化准备、风格探索、双主题试点样张及其迭代可自主推进；**最终全面设计须由用户明确批准后开始**。审批前先完成研究结论、可操作试点与建议适配范围，供用户审阅。认可某个样张或选择风格方向，不自动等于批准全面设计。

本轮已核对当前源码、现行工作流程、设计文档及部分实际设计画面：

- 当前应用为 React / TypeScript / Vite，采用自有 CSS；静态资源嵌入 Go 服务。
- 主要场景包括图像创作、多轮结果、六附件、图库与文件夹、大图预览、个人设置、积分历史、用户管理、请求记录和模型价格。
- 当前已有浅色／深色 CSS 变量、中文系统字体和少量加载动画；需要进一步形成字体、色彩、间距、形态、层级与动效的完整规范。
- 工作稿为 `design/ui-studio-design.figcraft`。本轮读取时已保存、无选区；01–05 页是当前界面，06 页为历史参考。
- 已有 37 个浏览器状态与设计画框的对照映射，可作为风格适配的回归基础。本轮未重新运行对照检查。

研究重点包括美术语言、信息组织、交互反馈及其适用条件。布局、组件造型和排版均可按风格重新设计；现有业务语义、渠道能力、附件次序、计费与失败处理是适配边界。

| 研究板块 | 主要来源 | 需要获得的结论 |
| --- | --- | --- |
| 官方品牌与网站 | 官网及相关页面、官方新闻与媒体包、海报、社交视觉、网页交互 | 视觉身份如何跨尺寸、媒介和信息量保持一致 |
| 游戏内界面 | 可核验版本的实机录制、菜单、设置、装备／物品界面、地图、HUD、提示和结果画面 | 信息优先级、导航、选择、焦点、状态与反馈如何工作 |
| 动画、CG、宣传片 | 官方预告、过场、片头片尾、动态标题、转场、字幕与图形叠加 | 时间节奏、图形运动、镜头与二维界面的关系 |
| 美术与制作过程 | 官方开发者内容、可核验参与者作品集、访谈、演讲、制作解析 | 设计意图、制作约束、形态与材质体系，以及作品的实际职责 |
| 分析与评论 | 高质量中英文美术／UI／动效分析视频和文章 | 可检验的观察、比较视角与争议点；回到原始材料验证 |
| 高质量二创 | 有作者与项目说明的界面概念、动态海报、字体实验、三维与平面作品 | 哪些特征可以被提炼、变形、扩展，哪些处理只适合单张展示 |
| 跨领域参考 | 瑞士／国际主义排版、实验平面与音乐视觉、工业与医疗仪器、导视、技术服装与包装、相关科幻界面 | 中文工具产品所需的排版、标记、材质和可读性补充 |

跨领域候选可包括 The Designers Republic、WipEout 等设计案例；它们在本方案中属于比较对象，是否存在对 Marathon 的真实影响需另有来源证明。

研究量目标：初筛约 40–60 个独立有效来源，深读／深看约 20–30 个；保留约 80–120 张有用途的截图与裁切、12–20 组动效序列。数量是规划区间，按公开材料质量调整，重复搬运和同一片段的转载不重复计数。资料分配以 Marathon 一手材料为主，跨领域扩展约占四分之一，避免把范围扩大为泛科幻资料合集。

检索同时使用中文和英文。保留重要版本的演进，但以研究时最新可核验材料为主；官网、宣传概念、测试实机与正式版本分别标识，不拼成一个虚构的“官方统一规范”。

荧光强调、巨型字与微排版、工业标识、精确栅格、材质反差等作为待检验方向。最终采用哪些、如何组合，由来源和本项目实样决定。

每项分析回答：看到了什么、为什么有效、适用条件是什么、如何转译到工作室。记录正例，也记录会干扰内容、只适合宣传、或在小尺寸下失效的反例。

## 4. 图文与视频证据方法

为每个来源记录编号、标题、作者／发布者、URL、日期、访问日期、版本与语言、来源类别、使用状态与证据置信度。视频另记录时间戳及必要的前后片段。

精选案例使用统一分析卡：

1. 原始全景，保留操作和信息环境。
2. 局部放大与标注，说明对齐、字阶、面积、线宽和状态变化。
3. 设计判断及其依据。
4. 映射到工作室的组件或场景。
5. 采用条件与需要改写的部分。

动效用连续关键帧和可回看的短片段／演示表达，写明触发、结束、可否中断。视觉估测的时长、缓动和色值标为估测；产品最终参数单独标为适配建议。

官方说明、直接观察、作者观点、研究推断分别标识。未知字体保留未知，同时给出有依据的近似替代；素材和字体记录许可，研究引用与可随产品分发的资产分开。AI 生成图仅可作为后续探索样张，明确标识，不充当游戏截图或研究证据；需要生成时按项目要求使用 CLI/API 方式。

## 5. 与当前项目的映射

| 项目场景 | 研究与设计任务 | 重点验证 |
| --- | --- | --- |
| 侧栏、账户区与导航 | 品牌锚点、分组、选中和折叠、计数、菜单 | 当前位置清楚，中文标签和窄窗口可读 |
| 创作输入区 | 提示词、多附件、模型与有效参数、数量、费用、发送 | 主次清楚，长文本、六附件和不可选参数处理准确 |
| 按钮与表单 | 主／次／危险操作、图标按钮、输入、下拉、切换开关、复选 | 默认、悬浮、按下、键盘焦点、禁用、处理中和错误可区分 |
| 滑动条 | 数值 slider 与滚动 scrollbar 分别研究；轨道、滑块、刻度与拖动 | 适合值域和精度；未存在的参数不为展示样式而加回业务页面 |
| 对话框与抽屉 | 文件夹、账户、用户、积分、请求详情、未保存确认 | 遮罩、层级、焦点、开合、长内容与错误位置 |
| 生成过程 | 等待、处理中、部分成功、失败与中断 | 动效反映真实状态，结果及时出现，不虚构进度或暗示自动重试 |
| 图库与多选 | 日期分组、图片卡片、选择、批量归类、文件夹操作 | 扫视效率和图片优先级，不以强色污染看图体验 |
| 大图预览 | 舞台背景、图片切换、工具栏、说明 | 原图颜色与细节不受装饰、滤镜或动画影响 |
| 设置与管理表格 | 密集信息、数字、状态、筛选、分页、保存冲突 | 可读、易比较，风格在高信息密度下仍成立 |
| 空白与异常状态 | 空图库、无结果、输入错误、请求失败、权限限制 | 有风格但信息准确，提示能引导下一步操作 |

页面的风格强度可分层：品牌区域与主动作承担辨识度；内容区与数据区采用适合长期工作的表达；大图观察区优先保证中性与稳定。浅／深主题按同一语义体系分别设计，并分别调整背景层级、文本、边框、强调色、遮罩、阴影及动效对比，保证两套主题同等完整。

建立“页面／组件 × 交互状态 × 浅色／深色”的覆盖表。对两套主题分别检查中文可读性、键盘焦点、语义色、图片观看环境和动效辨识度；主题切换与跟随系统也纳入原型验证。若官方参考只提供其中一种明暗表达，另一套明确标注为本项目的适配设计，并保留推导依据。

## 6. 执行阶段与审阅节点

| 阶段 | 执行范围 | 授权边界 |
| --- | --- | --- |
| A–B：调研与规则 | 方法对照、工具小样验证、资料采集、深度拆解、体系建议与完整研究报告 | 可自主推进 |
| C：试点与比较 | 双主题代表页面、组件样张、动效演示、局部可操作原型及其迭代 | 可自主推进；用试点画框和研究原型承载 |
| C 完成后的审批包 | 研究结论、推荐方向、双主题试点、拟覆盖页面与状态、实施顺序和待决事项 | 完成可审阅成果后，请用户明确批准全面设计 |
| D：全面设计与适配 | 全站双主题页面、完整组件状态、设计稿系统改造及产品前端全面适配 | 仅在用户明确批准的范围内执行 |
| E：固化与交付 | 按已验证成果定稿规范、设计 skill 和同步记录 | 研究报告、规范建议及 skill 草案可提前整理；全面适配成果待 D 获批完成后定稿 |

试点在 `design/ui-studio-design.figcraft` 中使用明确命名的探索／试点页面或画框，先保存设计，再制作 `prototypes/` 内的对应演示；保留现有正式画面和中性基线。审批前通过有代表性的有限样张验证体系，不把全部页面逐一改造当作试点。阶段进展和当前授权记录在研究入口，后续执行沿用用户的明确决定。

### 阶段 A：资料地图与基础归档

先参考成熟的设计调研与界面盘点方法，以少量网页、视频和组件验证采集、分镜、去重、标注及图册流程，再扩大到正式资料集。完成来源索引、版本分类、第一批截图与动效采样，补齐本项目组件和状态清单。交付可浏览的资料地图及覆盖缺口。工具与方法初查见 [方法与自动化参考](sources/workflow-references.md)。

### 阶段 B：深度拆解与风格规则草案

完成图文案例、字体与色彩研究、形状和排版规则、UI 逻辑与动效拆解。将结论整理为“来源证据 → 设计规则 → 项目用途”的对应关系，形成初步 moodboard 和规则草案。

### 阶段 C：三种表达方向与真实页面样张

基于调研提出三种有区别的表达强度，工作名暂定：理性工业、强烈图形、混合表达。方向名称和具体形式可随证据调整。

三种方向都应用于同一组内容：创作页关键区域、图库局部，以及包含按钮／下拉／对话框／滑动条的组件样板。每种方向均提供浅色与深色成对样张，使用相同内容比较字体、用色、密度、形状和动效。可自主调整试点、增加必要的局部对照并迭代。完成后推荐一条主方向，连同研究结论、可操作演示及全面适配范围组成审批包，再请用户明确批准是否进入阶段 D。

### 阶段 D：全面设计与适配（需用户明确批准）

获得用户对本阶段范围的明确批准后，把选定方向扩展为完整组件状态、浅深主题、全站页面、动效分镜和浏览器演示。两套主题都覆盖最终适配页面及关键状态，演示提供主题切换。设计稿先修改并保存到指定 FigCraft 文档，再同步对应本地原型／前端内容。原生设计工具无法表达的运动，用明确分镜和浏览器演示补足。

先覆盖创作页、图库、大图预览和高频弹窗；再覆盖设置、管理表格及其余状态。以中文长内容、繁忙页面、失败／部分成功、窄窗口和键盘操作检验体系。

### 阶段 E：固化规范、设计 skill 与交付

根据真实组件和页面的使用结果修正规则，再整理成可复用 skill。设计改动按项目工作流执行相关审计和浏览器对照；前端改动执行受影响的类型、构建与局部交互验证。复用输入未变的有效证据，不重复无关检查。

完整研究报告、体系建议、双主题变量草案与设计 skill 草案可在全面设计审批前交付，标明哪些规则已有试点证据、哪些尚待全面页面验证。全面设计是否获批不影响已经完成的研究成果归档。

### 自动化与方法实施

优先复用成熟项目和现有工具，通过少量脚本串联。先验证可用性和实际节省的重复工作，再决定采用的范围；以下是已初查的候选，并非全部已安装或已完成效果验证。

| 环节 | 工具／方法候选 | 本项目采用方式 |

采用增量处理：记录输入校验和、工具版本、参数和输出清单，只重算变化的输入或规则；独立文件可有限并发处理，同一设计文档的修改按批次顺序执行。采集失败保留状态与原因，批处理可从已完成条目继续；字体、色彩、动效和业务语义等关键结论须回看原始材料。重复资料增加但不再带来新规则时，转向覆盖缺口与反例验证。

自动化脚本、配置及独立依赖保存在 `marathon-design-research/tools/`，缓存和生成中间产物保存在 `marathon-design-research/outputs/`。尽量复用现有运行时和可用工具；仅为实际要用的流程添加依赖，并记录复现命令，不把研究工具依赖加入产品前端。
