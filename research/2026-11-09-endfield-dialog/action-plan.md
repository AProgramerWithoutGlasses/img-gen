## 1. 目标、范围与依据

目标是在原稿的位置关系和操作顺序上，完成终末地风格的桌面生图输入对话框：灰阶表面、黄色模型与生成按钮、胶囊参数、统一边线和图标圆片、清晰文字、轻量交互反馈。

本次包括输入区域、底部工具栏、参数菜单、按钮提示、添加参考图后的附件条、附件悬停预览，以及右上角展开按钮直接打开的提示词编辑窗口。后者沿用已有功能，只补同一套局部风格和完整编辑状态。

仅处理这些与对话框直接相关的区域。导航、侧栏、作品结果卡、图库、设置、账户和管理窗口均不在本次范围；附件悬停预览也不会被扩大成作品结果卡重设计。不新增手机或窄屏方案，不借此调整全站主题。

依据按以下顺序使用：

1. 本次用户文字要求及五张图上的批注。
2. 指定的[对话框设计稿](../../design/对话框设计稿.figcraft)及同文件“终末地色板 · 亮色 / 暗色”。
3. [终末地风格调研](report.md)与[既有同类生图网站调研](../../docs/research/website-research.md)，作为风格和交互判断依据，不将其中的待采纳建议当作硬性规范。
4. [现行接口契约](../../docs/api-contract.md)，约束真实模型、附件、积分和请求行为。

旧 UI 设计文档只用来了解现状与定位代码，不作为这次风格化设计的模板。旧调研曾建议模型中性、tooltip 中性、暂不折叠附件；本次分别按用户要求采用黄色模型按钮、原稿式提示及附件展开。旧调研中的窄屏建议不纳入本轮。

## 5. 交互与补全状态

### 5.1 输入区、按钮和菜单

- 默认两行；输入、粘贴、重新编辑、完整编辑器回填和清空均按实际排版重新计算高度，长段落自然折行也计入可视行数，不能只数换行符。底部工具栏不随文字增长上移；附件条随主框顶部向上避让。
- 输入法组合输入不误触发送，保留现有 Enter／Shift+Enter 及个人发送偏好。
- 悬停提示仅覆盖底部工具栏：添加图片、模型、当前实际支持的比例／分辨率、张数、积分、生成。按用户最新反馈，附件展开／收起、移除、右上展开编辑入口不增加可见悬停提示，保留图标操作和无障碍名称；这三类入口也不留会弹出原生提示的 title 属性。
- Tooltip 延迟约 350ms 出现，沿用原稿黄色小提示和指向触发器的小尖角；点击立即隐藏，鼠标离开触发器及提示区域后隐藏，Esc 可关闭，键盘聚焦也能查看。打开菜单时隐藏该按钮的 tooltip。
- 提示文字为12px、18px行高，底框高26px、左右各10px内边距，按实际字宽自适应，不沿用固定宽框，也不增加图标；文字水平、垂直居中。按用户最新反馈，亮暗主题的提示底框与尖角均无描边；亮色输入聚焦外框仅保留黄色边线，去掉深色内圈。
- 提示底框、文字和尖角作为一个整体放在独立浮层中，高于对话框及附件的边线，保留原触发器锚点。后续实现由统一浮层入口渲染，避免父级裁切或堆叠关系遮挡；不能只将文字单独提到上层。
- 桌面界面底部预留40px给下方提示和余量；当前静态稿包含1440×900亮暗示例，主框底边距画面底边40px；提示底框放大至26px，连同尖角仍须完整显示。真实页面的留白与遮挡在本次适配阶段核对。
- 菜单一次只开一个；点击按钮切换开关，选项选择后关闭，外点和 Esc 关闭；上下键移动、Enter 选择、关闭后焦点返回触发器。当前项用右侧圆点，悬停、按下和键盘焦点分别可辨。
- 模型、比例、分辨率、张数采用同套菜单外观；按用户最新反馈，模型按钮统一使用向上的箭头，不随菜单开合翻转；生成保留向上的提交箭头，两者圆片尺寸一致。
- 模型按钮及模型菜单逐字使用第 5.3 节的显示简写。比例、分辨率和张数按钮仅显示“自动”“1K”“1张”等短值，不改为“比例 自动”“分辨率 1K”或“张数 1”；说明放 tooltip 和无障碍名称中，不增加按钮可见文字。
- 右侧积分维持紧凑控件，tooltip 明确“预计消耗 N 积分”，与“生成张数”区分；按修订6删除点击积分按钮时的全局消息提示，不删除其他业务通知。报价未就绪、余额不足和提交中分别补态。数值来自现有服务端数据，不能用设计示例冒充实际报价。
- 完整提示词窗口沿用当前入口与完成／取消逻辑；补深浅主题、长文本、按钮对齐和焦点返回，只限定在该编辑窗口作用域。

### 5.2 附件条与悬停预览

附件条继续在对话框上方左对齐，紧凑显示最多三张图片及展开箭头；按用户最新补充，收起时始终宽 344px，1／2 张也保持三张时的宽度，不用空白图片卡填格，不显示 +N。展开后同一位置向右延伸到主框宽度 1080px，最多六张全部可见，右端保留收起箭头。展开／收起不改变图片顺序，不新增重排序。用户选择的展开／收起状态按当前用户保存在本机，刷新、清空附件及切换页面不重置；首次没有已保存选择时默认收起。

展开／收起按钮同步为 72 × 72px，占位关系不变，采用圆角 12px、内缩 2px 的 0.5px 深色细边线及居中的细线方向箭头，展开向右、收起向左；默认底色深色主题 #EEECEC、浅色主题 #FFFFFF，悬停整块变为 #FFFA00，按下 #E6DE00，箭头和边线为 #333333。颜色过渡约 120–160ms；不增加可见 tooltip，悬停该按钮不触发图片预览。

缩略图取 72 × 72px、圆角约 8px，条高 88px；按用户反馈，附件条与主框之间的整段距离为 14.716px，由黄条上下各 4.528px、黄条高 5.66px 构成。**真实图片必须铺满小格**，用裁切填充保持比例，不拉伸，不留随意空白；移除按钮覆盖在本张右上角，约 24 × 24px，默认隐藏，仅悬停本张缩略图或本卡键盘聚焦时显示；不能悬停整条后显示全部移除按钮。上传中和失败占位也沿用相同格尺寸及本卡悬停移除规则，不能导致整个工具栏跳动。

悬停预览沿原稿位于附件条上方，默认左缘与附件条对齐，间隔为 10.188px。当前预览框为 384 × 384px，图片区 376 × 344px、左上内缩 4px；文件名底片尺寸 368 × 24px，14px 字、20px 行高独立显示，随预览同步放大：

- 小格使用裁切填满，大预览使用完整图片适配；横图、竖图、方图都保持比例，剩余空间是有意设计的中性画布。
- 大预览默认隐藏，仅由对应缩略图悬停触发；空白处、展开／收起按钮不触发。静态稿中显示大预览的画板已标明悬停第几张，独立预览细节页是“悬停后内容”示例，不代表常驻。
- 图片名不压在图片上，长名省略，完整名称通过可访问名称或补充提示取得，不撑大浮窗。
- 指针在附件之间切换时更新同一预览位置，不跟随指针乱跑；移入预览可继续查看，离开两者后短暂延迟关闭，避免闪断。
- 指针从图片移入本卡移除按钮时不闪失；移除点击不再打开预览，删除对应图片后关闭其预览。预览绑定稳定附件 ID，移除或排序索引变化后不串图；离开缩略图时取消尚未执行的打开计时。上传中／失败且无可解码图片时不显示成功图片预览。
- 键盘聚焦也能查看附件内容；焦点样式和移除操作可辨，Esc 关闭预览。图片预览不截走附件删除所需焦点。
- 图片等待加载、失败、透明背景、不同纵横比均补画；高度不足时优先压缩预览图片区并限高，保留上方锚点关系。
- 附件下方黄色短条为用户明确的展开定位装饰，68 × 5.66px，上下间距各 4.528px；相对附件条左缘固定距左 121px，不随图片数量或展开／收起变化，不当作上传进度或拖拽把手。

## 6. 动效方案

动效取自终末地研究的轻量反馈方法；静态稿已有起止状态和时长标注，下列节奏已用于上一版网站实现并经浏览器核对，本次保持。修订 6 按第 4–5 节最新位置、尺寸、固定上箭头和无描边提示适配，不能因沿用动效恢复旧尺寸与配色。

| 动作 | 本轮实现 |
| --- | --- |
| 按钮悬停／按下、焦点描边 | 120–160ms 颜色和边线过渡；不整体跳动或放大 |
| 菜单开合 | 菜单在按钮上方，打开约 180ms 淡入并上移 4px 至终态，即 translateY(4px) → 0；关闭约 120ms；不弹跳 |
| Tooltip | 悬停约 350ms 后，以约 120ms 淡入；点击时立即关闭 |
| 附件条展开／收起 | 约 200ms 水平延展；左锚点、条高和主框底部稳定 |
| 附件预览 | 停留约 200ms 后、约 140ms 淡入；切换附件不做大幅位移 |
| 输入自增长 | 跟随实际排版立即更新，避免每次输入都做高度缓动；不出现弹簧或回弹 |

减少动态效果偏好下去掉位移与宽度缓动，保留清晰的最终状态。无持续扫描、闪烁、背景角色、开屏或音效。

动效验收在同一真实浏览器里核对亮／暗主题，以及快速移入移出、连续切换菜单、附件展开后立即收起、切换预览、输入增长后删除、减少动态效果等过程；检查动画中途也不跳位置、不裁切、不残留旧提示。提供相关动态过程证据和终态截图后，才能将此阶段标为完成。

验证范围按[测试说明](../../tests/README.md)唯一矩阵执行，这里只说明本次阶段如何使用：

- 仅更新报告或累计记录时：运行 `npm run check:docs`，核对报告链接；不把说明更新计作功能实现或发布。
- 静态阶段：对指定文件分别执行 `npm run design:audit -- "design/对话框设计稿.figcraft"` 和 `npm run design:export -- "design/对话框设计稿.figcraft"`；人工检查相关导出、文字对比度、重叠遮挡及原页保留。不能给固定复合命令追加路径而假定已切换稿件。
- 实施阶段：执行受影响前端检查和真实浏览器流程；完整 `verify` 已含构建和七条模拟流程，相同输入不重复构建。新增验证放独立测试目录，重点验证用户可感知行为，不为尺寸常量另写自我比对测试。
- 新行为重点：菜单选择与提交参数一致、外点／Esc／焦点返回、提示关闭、两行到上限再清空、中文输入法、六附件及顺序、单张悬停移除和预览、快速移走与删除后无残留、展开按钮黄色悬停且不触发预览、无 +N、展开／收起、完整预览、上传／报价异常、无自动重试、减少动态效果。
- 提示层级与留白：12px字和26px紧凑底框不裁字，尖角不被主框或附件边线压住；桌面底部预留位置后仍能完整显示提示，不改成无意的翻边位置。
- 显示简写核对：五个模型按钮及菜单名称逐字一致，切换后提交的模型 ID 与原值对应，模型能力及报价逻辑不受简写影响；检查参数按钮仍仅显示短值，其他页面未被批量改名。
- 桌面核对：以 1440 × 900 为主，并检查常见 1280、1920 桌面和受限高度；这是现有桌面布局的容纳检查，不新增窄屏或手机设计。
- 本次独立稿需明确建立相同状态的设计／浏览器截图映射或逐张对照。现有 `design:compare` 固定指向旧主稿，不能直接拿它证明本次独立稿已同步。
- 上线前完成实际 Go/CSP 联调；数据库测试只用空的专用 `_test` 库。缺少测试条件就明确标为未验证，不把模拟结果算成真实联调通过。不调用收费生成或润色接口验证样式。

## 9. 主要风险与处理

| 风险 | 处理 |
| --- | --- |
| 自定义菜单破坏键盘与输入法行为 | 明确菜单焦点和输入焦点边界，实际点击／键盘／中文输入法验证，复用现有发送偏好 |

| 用户原稿或协作者改动被覆盖 | 每阶段重查文档未保存状态与工作区；在同文件新页设计，原页保留；不重置、不隐藏、不夹带未确认改动 |
