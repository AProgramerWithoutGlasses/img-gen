## 1. 目标、范围与依据

目标是在原稿的位置关系和操作顺序上，完成终末地风格的桌面生图输入对话框：灰阶表面、黄色模型与生成按钮、胶囊参数、统一边线和图标圆片、清晰文字、轻量交互反馈。

本次包括输入区域、底部工具栏、参数菜单、按钮提示、添加参考图后的附件条及附件悬停预览。按最新反馈，右上角展开编辑按钮及其完整提示词编辑窗口功能均移除，提示词直接在主输入区编辑。

仅处理这些与对话框直接相关的区域。导航、侧栏、作品结果卡、图库、设置、账户和管理窗口均不在本次范围；附件悬停预览也不会被扩大成作品结果卡重设计。不新增手机或窄屏方案，不借此调整全站主题。

依据按以下顺序使用：

1. 本次用户文字要求及五张图上的批注。
2. 指定的[对话框设计稿](../../design/对话框设计稿.figcraft)及同文件“终末地色板 · 亮色 / 暗色”。
3. [终末地风格调研](report.md)与[既有同类生图网站调研](../../docs/research/website-research.md)，作为风格和交互判断依据，不将其中的待采纳建议当作硬性规范。
4. [现行接口契约](../../docs/api-contract.md)，约束真实模型、附件、积分和请求行为。

旧 UI 设计文档只用来了解现状与定位代码，不作为这次风格化设计的模板。旧调研曾建议模型中性、tooltip 中性、暂不折叠附件；本次分别按用户要求采用黄色模型按钮、原稿式提示及附件展开。旧调研中的窄屏建议不纳入本轮。

### 4.4 圆角、内框与局部层级

本轮设计稿所有 UI 圆角矩形均设置 iOS 模式、平滑度 0.6，内外框保持一致；圆形／椭圆不改成矩形。网页的 [dialog-corners.css](../../frontend/src/features/create/dialog-corners.css) 用原生 `superellipse(1.6)` 作视觉近似，该参数并非 iOS 60% 的一对一映射，不能宣称两端曲线完全相同。网页圆形、满半径胶囊和 tooltip 保留 `round`；不支持 `corner-shape` 的浏览器保留普通圆角。

上轮内框变形来自分别缩放 x／y／宽／高，却未同步半径和固定内距：2px 内缩被放大为约 2.44–2.5px，40px 高的内框仍用 16px 半径。本次按外框尺寸、固定内缩及半径推导内框；CSS 由高度和内缩变量计算对应半径。后续尺寸修改不可单独缩放旧内框，完成后运行 [对话框圆角检查](../../tests/design/check-dialog-corners.mjs)；该检查读取当前打开的指定稿，并用内存中的旧几何负例确认能拒绝同类错误，不重放 outputs 中旧修订脚本。

账户菜单遮挡来自对话框层级 20 高于侧栏祖先层级 10。本次仅将对话框局部层级降为 1，账户和侧栏布局、全局菜单样式保持原样。

## 6. 动效方案

动效取自终末地研究的轻量反馈方法；静态稿已有起止状态和时长标注，下列节奏已用于上一版网站实现并经浏览器核对，本次保持。修订 8 按第 4–5 节最新位置、尺寸、固定上箭头和无描边提示适配，不能因沿用动效恢复旧尺寸与配色。

| 动作 | 本轮实现 |
| --- | --- |
| 按钮悬停／按下、焦点描边 | 120–160ms 颜色和边线过渡；不整体跳动或放大 |
| 菜单开合 | 菜单在按钮上方，打开约 180ms 淡入并上移 4px 至终态，即 translateY(4px) → 0；关闭约 120ms；不弹跳 |
| Tooltip | 悬停约 350ms 后，以约 120ms 淡入；点击时立即关闭 |
| 附件条展开／收起 | 约 200ms 水平延展；左锚点、条高和主框底部稳定 |
| 附件预览 | 停留约 200ms 后、约 140ms 淡入；切换附件不做大幅位移 |
| 输入自增长 | 跟随实际排版立即更新，避免每次输入都做高度缓动；不出现弹簧或回弹 |

减少动态效果偏好下去掉位移与宽度缓动，保留清晰的最终状态。无持续扫描、闪烁、背景角色、开屏或音效。

动效验收在同一真实浏览器里核对亮／暗主题，以及快速移入移出、连续切换菜单、附件展开后立即收起、切换预览、输入增长后删除、减少动态效果等过程；检查动画中途也不跳位置、不裁切、不残留旧提示。提供相关动态过程证据和终态截图后，才能将此阶段标为完成。

## 9. 主要风险与处理

| 风险 | 处理 |
| --- | --- |
| 自定义菜单破坏键盘与输入法行为 | 明确菜单焦点和输入焦点边界，实际点击／键盘／中文输入法验证，复用现有发送偏好 |
| 浮层被主框裁切或与附件预览重叠 | 维持原锚点，用独立浮层层级、内容限高和视口约束解决；不对包含菜单的容器整体裁切 |
| 八行输入与图片预览叠加占高 | 底部锚定，附件随顶部移动，预览图片区按可用高度缩小；首稿就画两者同时出现的情景 |
| 新样式污染其他页面／窗口 | 使用对话框局部类名和变量，保持其他区域视觉不变，通过受影响浏览器流程核对 |
| 图示参数与真实渠道能力冲突 | GPT／Gemini／附件模式分开画并复用现有配置，不新增假可用控件 |
| 用户原稿或协作者改动被覆盖 | 每阶段重查文档未保存状态与工作区；在同文件新页设计，原页保留；不重置、不隐藏、不夹带未确认改动 |
| 静态图看不出真实动效与失败处理 | 静态审批只确认视觉方向与交互方案，实现后补真实浏览器动态和异常状态核对 |
