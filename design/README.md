# 设计到实现工作流

此流程用于本网站后续各区域的新样式与局部改版，不固定配色、尺寸、圆角或布局。设计决定以用户本次要求和已批准画面为准；旧 UI 说明、研究建议及历史稿只提供背景，不能限制新的风格探索。接口、权限、计费与数据安全约束仍按对应现行说明执行。

## 先确定目标与边界

用户指定的文件优先；未指定时使用 `design/ui-studio-design.figcraft`。只定位本次相关画面与代码，不为一次局部改版打开、重制或改变全站设计。

开工先用 `doc.list` 和指定文档的 `inspect_document` 核对路径、选区、当前页与 dirty 状态。保留用户未保存编辑、参考图和原稿；有未保存内容时基于当前现场继续，必要时先另存保护副本，不直接重载磁盘版本。

在同一份当前记录中区分以下用途，页面名和组标记应能看出来：

| 用途 | 实现边界 |
| --- | --- |
| 原稿、色板、参考与历史对照 | 可读取明确相关的依据；保持原内容，禁止自动提取为实现素材 |
| 候选方案 | 标明待确认和禁止自动适配；允许保留 A/B 对比 |
| 已批准画面 | 记录明确的页或组件组 ID、用途、状态和适配范围；只从这些对象同步 |
| 对照标题、中心线和审阅注释 | 标为 annotation/reference，不进入产品界面 |

同一页可能同时有已批准组件和旧参考，不能以“整页／整文件都是待实现素材”代替明确清单。批准某个候选后只激活选中的组，其余对照继续保留为参考；色板可以参与选色，也不因此成为动效素材。

以上是默认保护方式；用户明确指定修改原稿、替换参考或调整范围时，以本次指示为准，不把文件的历史身份当作永久限制。

## 先小样，再补全状态

1. 用本次范围、目标稿、当前批准状态和已有授权形成简短基线。清楚的任务直接推进，只有缺失信息会改变结果时才澄清，不重复询问已获授权的步骤。
2. 新风格先做代表组件与少量关键态，例如主容器、一个常用控件、一个浮层和亮暗对照；局部样式修复可直接更新对应状态。先让用户看得到主要变化，再批量补齐重复样式和完整状态，避免方向未定就铺开大量画板。
3. 用户要求“先静态、确认后实现”时，按这一阶段约定交付可审阅画面；批准后继续已授权的代码、动效与发布。没有这种约定的常规修复，不额外增加静态审批流程。
4. 静态确认后，将布局、视觉、文字、交互状态和组件关系同步至局部代码，保留既有业务语义；完成必要的轻量动效、键盘操作和减少动态效果支持。
5. 用真实浏览器核对当前批准画面和受影响交互，再按已授权范围交付或发布。反馈进入同一轮当前记录，更新最终结论，不逐条重放历史操作。

每个阶段只记录继续工作所需的最终选择、适配清单、待确认点和实际验证状态。普通小改不默认生成研究、行动、验收三套报告；需要长期复用的结论更新对应现行说明。

## 尺寸、光学与状态核对

判断“太大／太小”前先确认浏览器缩放、视口与系统缩放／DPR。设计尺寸使用 CSS 像素；同一画布按相同比例对照，原尺寸查看，必要时补局部放大。明确容器尺寸是否包含描边，以及描边是内部、居中还是外部，避免描边改变布局或被容器裁切。

几何中心相同不能直接证明肉眼观感一致，也不能只凭截图认定错位。先量可见轮廓、图标与文字中心，再用小样比较必要的光学补偿；一旦补偿被批准，将差值表达为明确参数。检查真实可见范围和命中区域，尤其是大圆钮超出工具栏、浮层及外部描边的情况。

缩放时按语义重排，不分别拉伸父子层后保留旧几何。内框宽高与半径由外框和固定内缩推导，图标保持比例，文字使用明确字号与行高。固定线宽、内距、光学差值和会随尺寸变化的量要分开表达，复用局部变量或参数，避免各状态手工漂移。

新样式可以改变圆角、描边、字体、颜色和密度；只改尺寸或间距的任务则保留未涉及的视觉决定。当前对话框使用的 iOS 0.6 平滑、圆钮差值和配色只属于该组件的已批准方案，不是后续其他区域的强制规范。工具与网页曲线能力不等价时说明实际近似与回退，例如原生 `superellipse` 参数不能直接当作 iOS 百分比。

最小状态集合按本次变化选择：默认／悬停／按下／聚焦／禁用，菜单当前项及开关，长文本增长与滚动，附件加载／失败／删除，以及浮层和现有账户、设置窗口的叠放关系。示例文案与数量只用于展示，不能据此改业务默认值、底层 ID 或请求参数。

## FigCraft 操作与连接

`figcraft.config.json` 是应用、CLI、离线兜底稿和控制端口的共享入口；其中 `document` 只供未指定文件的离线审计／导出及旧主稿对照使用，不决定应用启动时打开什么。本机安装路径可用忽略提交的 `figcraft.local.json` 或 `FIGCRAFT_APP`、`FIGCRAFT_CLI` 配置。个人代理、安装与授权方式不写成全员要求。

项目 MCP 通过官方 CLI 复用已运行的 FigCraft，并以 `figcraft-cli mcp --attach` 连接。只有请求携带明确文件目标时才允许按该目标启动应用；列工具、查状态或查询当前文档不会自动打开旧稿。若控制端口属于其他应用，或已有会话读写根目录不匹配，先保留现场再处理冲突，不关闭用户进程。普通代码或文档任务不需要连接设计工具。

用 `npm run design:open -- "design/目标.figcraft"` 按需打开本次目标稿；省略文件会提示补充，不打开兜底稿。`design:status` 只探测，应用未运行时返回未运行状态。处理设计时先读取可用会话的 `doc.list`；应用未启动时直接用明确目标的 `open_file` 或 `design:open` 启动，再核对现场。后续工具调用显式传 `document`，不要为一次任务改共享兜底稿路径。`design:snapshot` 不带目标时截取现有当前页，可追加节点 ID 和目标路径；批量写入使用 `design:batch -- commands.json "design/目标.figcraft"`，必须明确目标稿。

少量查询 `list_commands` 后，按依赖顺序用 `batch` 更新一组相关节点，编辑后保存。可长期复用的参数化操作放 `design/commands/`，一次性操作和证据放 `outputs/`。失败先读取实际状态，不自动重试，不重放旧建稿或缩放脚本恢复过时样式；需要复用时先核对输入、目标对象和参数。

| 能力 | 适用边界 |
| --- | --- |
| `design:snapshot` | 截取当前相关节点／画布；可查看未保存现场，不拿旧截图冒充当前结果 |
| `design:audit -- "design/目标.figcraft"` | 对明确的已保存文件检查字体等诊断；小改按风险选择，不替代视觉核对 |
| `design:export -- "design/目标.figcraft"` | 导出指定稿；优先用 API 只导出本次相关画板，避免重复全稿输出 |
| `design:verify` | 默认稿的审计加导出复合命令；追加路径不能假定两步都切换到指定稿 |
| `design:compare` | 现有 37 个状态映射属于默认主稿；只有对应目标与场景仍适用时才使用 |
| `design:smoke` | 设计连接、工具或自动化实现变化后的连通验证；先用 `design:open -- "design/目标.figcraft"` 建立会话，再运行自建临时 fixture 检查，不自动启动兜底稿；普通样式调整不重跑 |

这些是可用工具，不是每次任务都必须依次执行的清单。独立稿或新区域应对照其当前批准对象与真实浏览器，不用默认稿的旧映射证明同步。现有对话框几何检查也带特定范围；新区域先配置对应范围，不能硬套旧节点 ID。

## 验证、留存与交付

验证命令与范围统一见 [测试说明](../tests/README.md)，设计流程不复制另一份矩阵。一次累计修改后执行受影响检查；输入未变复用通过结果，只有新变化、失败或未解问题才补查。构建一次供截图、浏览器验证和发布复用；依赖未变不重装。并行任务应各自负责不同文件，并指定一个人统一运行检查，避免多名 agent 重跑相同输入。

视觉验收至少检查当前相关画面，业务状态在真实浏览器操作；等待图片加载和动画稳定后截图。静态图、几何检查、模拟 Provider、真实 Go/CSP 和真实上游各有证据边界，不能互相替代；视觉调整不调用收费生图或润色接口。真实接口约束见 [接口契约](../docs/api-contract.md)。

交付简要说明改了什么、对应画面、验证结果和实际状态；只在用户要求或确有共享价值时扩展报告。发布沿用 [部署流程](../docs/DEPLOYMENT.md)，不把本地完成、推送或服务启动单独当作上线成功。

`design/` 留可编辑稿、素材和可复用命令；`outputs/` 留临时截图、日志与恢复证据，不提交。保留用户原稿、参考图、未合入的设计修改和唯一备份。过时重复产物按实际恢复价值清理，资料归属和保留约定见 [工作流程](../docs/workflow.md#资料归属)。
